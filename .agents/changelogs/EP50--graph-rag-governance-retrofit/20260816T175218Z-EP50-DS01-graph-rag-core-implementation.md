## 1. Feature Overview

A knowledge graph built from the repo's own governance artifacts. The graph portrays **knowledge, not work**: nodes are workspace `domain`s, the `ryoiki` (named areas of knowledge within a domain, sourced from `KNOWLEDGE.md` headings) they contain, and `kettei` (architecture decisions — ADRs) that govern them. Stories and epics are never nodes — they are demoted to provenance metadata (`sources`/`epics`/`prs`) stamped on the ryoiki they produced, so "which work built this?" stays answerable without the graph fragmenting into a timeline of episodes.

Pipeline: read source artifacts (`KNOWLEDGE.md` files, `.agents/changelogs/archive/index.json`, ADRs under `product-documentation/architecture/`) → build an in-memory `ProjectGraph` → serialize to `.graph-data.json` → query it via keyword search + traversal + LLM reasoning, either from the CLI or a local server UI.

## 2. Core Requirements

| Requirement | Decision | Rationale |
| --- | --- | --- |
| Node model | Three types only: `domain`, `ryoiki`, `kettei` | Graph must portray knowledge and decisions, not a work timeline |
| Story/epic representation | Provenance metadata on `ryoiki` nodes, never graph nodes | Prevents the picture fragmenting into an episode-by-episode breakdown |
| File representation | No `file:` nodes | The graph never duplicates what git already stores |
| ADR entry into graph | Gated on `**Decides:**` field + `.graph-rag-config.json` allowlist | Nothing enters the graph floating/unlinked |
| Node dedup | Last-write-wins by `id` | Simple, deterministic re-ingestion |
| Edge dedup | Unique `(from, to, type)` | Prevents duplicate relationship spam on rebuild |
| Storage | `.graph-data.json`, gitignored, regenerated by `graph:build` | Cache, not source of truth — same inputs always regenerate the same graph |
| Query retrieval | Key-free keyword search + traversal | No LLM call needed to find the relevant subgraph |
| Query reasoning | Anthropic client (`engine.query()`); server UI routes to local Ollama instead | Separates the reasoning backend used by the CLI/API from the one used by the interactive UI |

## 3. Data Structures

```typescript
// src/types.ts
export type NodeType = 'domain' | 'ryoiki' | 'kettei';

export interface Node {
  id: string;
  type: NodeType;
  label: string;
  metadata: Record<string, unknown>;
}

export type EdgeType = 'contains' | 'relates' | 'decides' | 'supersedes';

export interface Edge {
  from: string;
  to: string;
  type: EdgeType;
  label: string;
}

export interface GraphData {
  nodes: Node[];
  edges: Edge[];
  summary: {
    totalNodes: number;
    nodesByType: Record<NodeType, number>;
    totalEdges: number;
  };
}

export interface GraphContext {
  query: string;
  relevantNodes: Node[];
  subgraph: { nodes: Node[]; edges: Edge[] };
  graphStats: {
    totalNodes: number;
    totalEdges: number;
    nodeTypes: Record<NodeType, number>;
  };
}

export interface QueryResult {
  query: string;
  answer: string;
  context: string;
  nodes: Node[];
  edges: Edge[];
}
```

## 4. User Workflows

```
BUILD:
START → `pnpm --filter @gll/graph-rag graph:build`
      → buildProvenanceIndex(archive) [no nodes]
      → ingestKnowledge(KNOWLEDGE.md files, provenance) → domain/ryoiki nodes + contains/relates edges
      → ingest ADRs allowlisted in .graph-rag-config.json → kettei nodes + decides/supersedes edges
      → serialize → .graph-data.json
      → END

QUERY (CLI):
START → `pnpm --filter @gll/graph-rag graph:query "<question>"`
      → keyword search over nodes → traverse subgraph → Anthropic client reasons over context
      → answer printed
      → END

QUERY (UI):
START → `pnpm --filter @gll/graph-rag graph:ui`
      → serve.ts starts local server, ui.html renders graph
      → user query → routed to local Ollama for reasoning
      → linking UI: user links a floating ADR to a ryoiki/domain
      → POST /api/link → decides edge added + written back into ADR's **Decides:** field
      → END
```

## 5. Stories

### EP50-ST01: Provenance index reader

**Scope**: Build the provenance-only index from the changelog archive — produces no graph nodes.
**Read List**: `src/readers/archive.ts`, `.agents/changelogs/archive/index.json`
**Tasks**:

- [x] `buildProvenanceIndex(archive, filter)` reads `.agents/changelogs/archive/index.json`
- [x] Produces `byRyoiki`: `(domain, ryoiki) -> { stories, epics, prs }`
- [x] Produces `epicSpan`: `epicId -> set of ryoiki keys it produced`
      **Acceptance Criteria**:
- [x] Function produces no graph nodes — index only
- [x] Unit tested

### EP50-ST02: Knowledge ingestion

**Scope**: Parse `KNOWLEDGE.md` files into `domain`/`ryoiki` nodes and their edges.
**Read List**: `src/readers/knowledge.ts`, an example `KNOWLEDGE.md` (e.g. `packages/srs-engine/KNOWLEDGE.md`)
**Tasks**:

- [x] `ingestKnowledge(graph, root, filter, provenance)` reads `<root>/{apps,packages}/<unit>/KNOWLEDGE.md`
- [x] One `domain` node per `KNOWLEDGE.md` (id = `unit` frontmatter)
- [x] One `ryoiki` node per `##` heading, `content` = prose beneath it, stamped with provenance from ST01
- [x] `contains` edge: domain → ryoiki
- [x] `relates` edge: ryoiki → ryoiki, for cross-domain ryoiki sharing an epic
      **Acceptance Criteria**:
- [x] Stories/epics never appear as nodes — citations only
- [x] Unit tested (`ryoiki-reader.test.ts`)

### EP50-ST03: Core graph engine

**Scope**: In-memory graph storage, dedup, and serialization.
**Read List**: `src/graph.ts`, `src/types.ts`
**Tasks**:

- [x] `ProjectGraph` class: `Map<id, Node>` + `Edge[]`
- [x] Node dedup: adding an existing `id` overwrites (last-write-wins)
- [x] Edge dedup: unique `(from, to, type)`; `relates` pairs ordered deterministically so `A→B`/`B→A` collapse
- [x] Serialize to `packages/graph-rag/.graph-data.json` (gitignored)
      **Acceptance Criteria**:
- [x] Same artifacts in → same graph out (deterministic)
- [x] Unit tested (`graph.test.ts`)

### EP50-ST04: ADR/kettei reader and linking

**Scope**: Ingest ADRs as decision nodes, gated on an explicit link, plus the write-back that authors that link.
**Read List**: `src/readers/adr.ts`, `src/server/serve.ts` (`POST /api/link`), one ADR under `product-documentation/architecture/`
**Tasks**:

- [x] Parse ADRs into `kettei` nodes: `slug`, `status`, `date`, `deciders`, `scope`, `content`, `decides[]`, `path`
- [x] `kettei` enters the graph only once `**Decides:**` is authored against an existing ryoiki/domain node AND the ADR is in `.graph-rag-config.json`'s `adrs.files` allowlist
- [x] `decides` edge: adr → ryoiki | domain
- [x] `supersedes` edge: adr → adr, auto-parsed from `Superseded by` / `Amended by` links
- [x] `POST /api/link` in `serve.ts` writes the link back into the ADR's `**Decides:**` field
      **Acceptance Criteria**:
- [x] An ADR with no `decides` edge is "decided, not yet built" — stays out of the graph
- [x] Unit tested (`adr-reader.test.ts`)

### EP50-ST05: Config-driven filtering

**Scope**: Scope the graph by track/domain, and gate which ADRs are eligible.
**Read List**: `src/config.ts`, `src/readers/ryoiki-config.ts`, `.graph-rag-config.json`
**Tasks**:

- [x] `buildGraph(root, { tracks, domains })` filters: `tracks` keeps only provenance from stories on those tracks; `domains` keeps only listed workspace units
- [x] `null`/omitted filter = no filtering

- [x] Filtering only affects provenance/inclusion, never mutates ryoiki content
